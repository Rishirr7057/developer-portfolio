# Rishi Kumar Gupta | Portfolio product requirements

## Purpose

Help recruiters assess Rishi for early-career full-stack and software development roles. Help engineering interviewers identify concrete topics to discuss. The portfolio's differentiator is four independently built client applications across manufacturing, fitness, travel, and retail.

## Audience and visitor journeys

- **Recruiter screening.** Identify the candidate, target role, primary stack, internship, and expected graduation on the first screen. Open selected work, download the résumé, or contact Rishi in one action.
- **Technical evaluation.** Scan all four applications, then use the case studies to understand the business workflow, Rishi's ownership, the integration or data constraint, and the technologies used.
- **Interview follow-up.** Use a direct project link for a focused conversation, or reach Rishi by email or LinkedIn. GitHub links to the candidate profile.

## Content and information architecture

1. **Hero.** State the role, practical specialization, evidence from the internship, and graduation year. Provide project and résumé actions.
2. **Selected work.** Keep the four projects in résumé order. Put the system's purpose and primary contribution on each card. Provide an optional deeper walkthrough with a workflow and an implementation rationale. Give each project a stable anchor.
3. **Engineering approach.** Explain how Rishi maps operational workflows, keeps records consistent, and handles external integrations. Link each principle to relevant client work.
4. **Experience.** Describe the engineering internship and preserve the dates and responsibilities of Paytm and Airtel roles. Add relevant context about merchant onboarding and operational handoffs.
5. **Skills and education.** Prioritize the core stack and pair technical skills with project evidence. Keep foundational tools clearly labeled. Preserve education dates and institutions and omit percentage scores on the webpage.
6. **Contact.** State the roles Rishi is targeting and offer clear email, LinkedIn, GitHub, phone, and résumé actions.

## Editorial and implementation constraints

- Use first-person copy that explains what Rishi built and why each workflow matters. Write for recruiters and engineers in plain English.
- Preserve source facts from the résumé. Add outcome metrics, code links, screenshots, or client claims when Rishi supplies evidence and has permission to share them.
- Keep the site static and the existing portrait, light-by-default theme, saved theme preference, and reduced-motion support. Use native disclosures for deeper case studies, with core evidence visible on each card.
- Preserve the downloadable résumé and existing hosted access policy. Recruiter access must be granted or configured before sharing externally.

## Acceptance criteria

- The hero identifies the role, PHP/MySQL/JavaScript, four client applications, and expected graduation.
- Every project has a clear business purpose, specific personal contribution, stack, and a keyboard-operable walkthrough.
- Engineering approach connects principles to named examples. All original experience and education entries remain available.
- Project anchors, résumé download, and contact actions work. Content is readable at mobile and desktop sizes in both themes.
- The published version reflects the verified build. The PRD is available as an editable project file.
